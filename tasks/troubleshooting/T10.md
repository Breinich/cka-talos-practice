# T10 — Trace kubelet to its runtime

| Field | Value |
|---|---|
| Task ID | `T10` |
| CKA pillar | `troubleshooting` |
| Mode | `read-only` |
| Capability | `talosctl` |
| Points | 2 |

## Scenario

Read-only **Talos** investigation. The shared `toolbox` Pod uses the node default runtime; no host SSH, `crictl` install, restarts, or configuration edits are allowed.

## Required outcome

Identify a node running `toolbox` and inspect its Kubernetes `containerRuntimeVersion` and Pod `runtimeClassName` (empty string if unset). On that same node run `talosctl -n <node> service kubelet` and `talosctl -n <node> service containerd`; inspect their state. Save `.lab/evidence/T10.json` with `node`, `runtimeVersion`, `podRuntimeClass`, `kubeletService`, `containerdService`; service values must be `Running`. The validator compares the runtime to the node and queries both Talos services live. If Talos API access is absent, expect UNSUPPORTED.

## Safety boundary

Read-only; no node, control-plane or Talos machine changes.
