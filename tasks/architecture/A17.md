# A17 — Plan a highly available Talos control plane

| Field | Value |
|---|---|
| Task ID | `A17` |
| CKA pillar | `architecture` |
| Mode | `simulation` |
| Capability | `core` |
| Points | 3 |

## Task

Write `.lab/evidence/A17.txt` describing a highly available Talos control-plane design: an odd control-plane/etcd member count, stable load-balanced API endpoint, failure-domain placement, quorum behavior, certificate SANs, and the Talos machine-configuration patches and safe sequencing used to add, replace, or upgrade a member. Include validation and rollback gates. Do not apply machine configuration or change cluster membership.

## Safety boundary

Planning only. Do not run `talosctl apply-config`, bootstrap, reset, reboot, upgrade, or etcd membership mutations on the homelab.

## Validation

From the repository root:

```bash
./scripts/validate.sh --task A17
./scripts/validate.sh --task A17 --json
```

The validator checks two independent architecture/safety criteria and returns `PASS`, `PARTIAL`, or `FAIL` without printing a solution. Answers and hints remain separate under `answers/`.
