# A16 — Model an operator lifecycle safely

| Field | Value |
|---|---|
| Task ID | `A16` |
| CKA pillar | `architecture` |
| Mode | `simulation` |
| Capability | `core` |
| Points | 2 |

## Task

Create `.lab/evidence/A16-operator.yaml` as an offline operator lifecycle model containing a CRD, controller Deployment, ServiceAccount, least-privilege RBAC and binding, and one custom resource. Parse the file offline, then record in `.lab/evidence/A16.txt` how install, configuration, upgrade, rollback, and removal ordering protect existing custom resources. Do not apply the operator or its cluster-scoped resources to the homelab.

## Safety boundary

Create only the requested local artifact under `.lab/evidence/`. Operator CRDs and cluster-wide RBAC must not be applied to this cluster.

## Validation

From the repository root:

```bash
./scripts/validate.sh --task A16
./scripts/validate.sh --task A16 --json
```

The validator checks manifest completeness and lifecycle evidence and returns `PASS`, `PARTIAL`, or `FAIL` without printing a solution. Answers and hints remain separate under `answers/`.
