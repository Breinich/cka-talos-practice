# A15 — Inventory admission without changing it

| Field | Value |
|---|---|
| Task ID | `A15` |
| CKA pillar | `architecture` |
| Mode | `read-only` |
| Capability | `core` |
| Points | 2 |

## Scenario and objective

Inspect `kubectl get validatingwebhookconfigurations,mutatingwebhookconfigurations` and the active lab namespace labels. In `.lab/evidence/A15.json` record `validatingWebhookCount`, `mutatingWebhookCount`, and `podSecurityEnforce` (`unset` if absent). Verify the counts against the live lists and namespace label; do not submit a privileged probe Pod or edit shared admission objects.

The active namespace is `CKA_LAB_NAMESPACE` (default `cka-practice`); the active prefix is `CKA_LAB_PREFIX` (default `cka-practice`). If setup used flags, export matching `CKA_LAB_PREFIX` and `CKA_LAB_NAMESPACE` before validation; `.lab/state.env` records their values.

## Safety boundary

Observation only; do not change cluster resources, certificates, host configuration or services. All created cluster objects require `cka-lab.io/owner=cka-talos-practice`. Never commit `.lab/evidence` or credentials.

## Validation

```bash
./scripts/validate.sh --task A15
./scripts/validate.sh --task A15 --json
```

Two independent outcomes are scored where applicable; offline/disposable limits are called out above. Evidence observations should be reviewed against their sources when a remote endpoint is not available to the scorer.
