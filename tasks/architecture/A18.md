## Scenario and objective

The synthetic collector at `samples/architecture/component.yaml` is not a real cluster service. Copy the bundled component into `.lab/evidence/A18-overlay` and create a Kustomize overlay there (Kustomize does not allow a base outside its load root); render `.lab/evidence/A18-component.yaml` with `kubectl kustomize`. Adjust to two replicas and the active namespace, preserving the owner label on Deployment and Pod template. The scorer independently rebuilds your overlay and compares semantic output with the saved render. Do not apply the component.

The active namespace is `CKA_LAB_NAMESPACE` (default `cka-practice`); the active prefix is `CKA_LAB_PREFIX` (default `cka-practice`). If setup used flags, export matching `CKA_LAB_PREFIX` and `CKA_LAB_NAMESPACE` before validation; `.lab/state.env` records their values.

## Safety boundary

Local artifacts only; never apply cluster-scoped definitions or rendered components. All created cluster objects require `cka-lab.io/owner=cka-talos-practice`. Never commit `.lab/evidence` or credentials.

## Validation

```bash
./scripts/validate.sh --task A18
./scripts/validate.sh --task A18 --json
```

Two independent outcomes are scored where applicable; offline/disposable limits are called out above. Evidence observations should be reviewed against their sources when a remote endpoint is not available to the scorer.
